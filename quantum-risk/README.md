# Entanglement Entropy Score experiment

This directory contains Qu-Alz's experimental quantum-feature path. It encodes MRI-derived feature vectors with a Qiskit `ZZFeatureMap`, computes a reduced density matrix from the simulated statevector, and uses von Neumann entropy as an Entanglement Entropy Score (EES).

The score is a research feature generated by this implementation. It has not been established as a medical biomarker, a diagnostic measure, or evidence of quantum advantage.

## Method

```text
MRI image
    -> ResNet18-based 64-dimensional feature vector
    -> 10-qubit ZZFeatureMap
    -> statevector simulation
    -> 5:5 bipartition and partial trace
    -> reduced density matrix
    -> von Neumann entropy
    -> EES
```

The current implementation uses Qiskit Aer statevector simulation. It does not run the EES experiment on quantum hardware.

`MRIEmbeddingExtractor` starts from a pretrained ResNet18 backbone and replaces its final layer with a 64-output layer. The repository does not preserve evidence that this replacement layer was trained for the EES experiment, so the generated score should be interpreted as a prototype computation rather than a validated image representation.

## Generated outputs

[`ees_results.csv`](ees_results.csv) stores per-image scores and run metadata generated by the experiment. Repository-level plots are available under [`../docs/results/quantum/`](../docs/results/quantum/).

The class-level means in those artifacts show how the implemented score varied across the included image labels. They do not establish statistical separation, generalization, clinical validity, or causal relevance to Alzheimer's disease.

## Run the experiment

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python test_quantum_ees.py
```

To compute scores for an available local dataset:

```bash
python compute_all_ees.py
```

The scripts expect MRI image folders arranged by the four prototype classes. Dataset licensing and access are not managed by this repository.

## Research boundary

- The EES computation is simulated classically with Qiskit Aer.
- No classical-feature ablation or matched baseline establishes added predictive value from EES.
- The repository does not preserve a held-out clinical evaluation.
- The feature-fusion model uses category-derived target values and must not be interpreted as a prospective risk model.
- Outputs are for research inspection only.
